## 何を追加したか

- 出撃3人の左上縦並びUI：中央メダル、透過装飾枠、SVGの赤HP・紫狂気ゲージ。数値は常時表示せず、aria-labelには残す。
- 手札4→5枚。扇形配置、中央を高く、選択時12px浮き・1.12倍・発光・前面化。
- 戦略カード3種を通常手札にランダム混在。固定スロット・固定ボタンではない。
- 固定の豪華な下枠と、各カードと一緒に動く独立カード枠。停止・速度の枠も固定素材内に含む。
- 短いiPhone Safari表示を優先する配置。アプリ高さ/幅<1.95でコンパクトになる。
- 味方・敵の描画高さを85%。全5人の初期上下値を+20。
- 防衛線・有効範囲・拠点突破判定を元から60表示px下へ。

## 何を消した／隠したか

- 戦闘中の「逆転の右手」ボタンは非表示。内部の巻き戻し機能と敗北画面の巻き戻しは残る。削除済みと誤解しないこと。
- 戦闘の右専用レール領域を廃止し、戦場を全幅へ。停止・速度ボタンは下部右に残す。
- 旧4枚手札レイアウトを戦闘では新5枚配置で上書き。探索の行き先カードは別扱いで維持。
- 旧下枠・独立ボタン枠画像はフォールバックとして保持するが、現在は抽出モックの固定下枠を優先する。
- 固定下枠から5枚の空カード枠を除去。カードを浮かせても固定側に空枠が残らない。
- 味方足元HPバーは元実装に存在しなかったため、削除した実績はない。影・オーラは維持。
- メダル追加時に一度外枠を非表示にしたが、現在は復帰済み。メダルと外枠は共存する。

## 戦略カードの仕様・ロジック変更の境界

|カード|実際の効果|装填秒|
|---|---|---:|
|癒しの光|生存味方を最大HPの35%回復、蘇生しない|18|
|運命の引き直し|自身以外の手札を山札へ戻して引き直す|14|
|再起の号令|自身以外の空スロットの装填待ちを解除し補充|20|

通常攻撃のクールタイムをリセットする実装ではない。味方強化・陣形強化はモック例だけで、未実装。戦略は種別ラベル、色調、名前帯、SVGモチーフで区別する。専用絵はまだ仮。

編成の生存味方のスキルカードを作り、旧rcによるシャッフル消費を維持した後、戦略3枚を追加して専用B.rdでシャッフル・抽選。B.rdはseed^0x6A09E667から生成。敵の標的選択もrcを使うので、カード増加のためにrc消費を変更しない。

UIだけの変更と言い切らないこと。5枚化、ランダム補充、戦略効果、防衛線移動はゲームへの変更。戦場拡張に伴う論理Hも接敵時間へ影響する。既存攻撃ダメージ等を全面改変したわけではない。85%描画のみの変更は同条件60秒の戦闘状態一致を検証した。

## 画像はどこにあり、どう入るか

編集元：`dev/naraku_src.html`。配布：ルート `index.html`。`index.html` 内のUI画像はbase64 data URLに埋め込み済みで、実行時に素材フォルダから取得する構造ではない。画像だけ差し替えても配布HTMLを再ビルドしなければ公開表示は変わらない。巨大なindex.htmlを全文読み出して解析しないこと。

|---|---|---|

|ui_battle_extracted_card_frame.webp|720×1106|可動カードの縁、中央透過|
|ui_battle_status_frame.webp|768×768|左上の二重円装飾枠、中央・帯・外側透過|

元素材保管先：`dev/cardart/battle_ui_materials/`（4枠の元JPEGと透過PNG）、`dev/cardart/battle_ui_extracted/`（抽出モック元JPEGと分離透過PNG）、`dev/cardart/battle_medals/`（5人の元JPEG）。枠の透過・分離は画像生成による派生で、完全なピクセル抽出ではない。メダルは再描画せず縮小したもの。

`UI.battle_extracted_*`等として自動埋め込み。BATTLE_CARD_FRAMEは抽出→初期案→旧汎用枠の優先順。顔はUI['battle_face_'+id]、なければ既存paintHeadフォールバック。スキル絵は既存UI.card_<owner>。戦略の差し替えキーはUI.battle_strategy_heal/redraw/reset、未登録時はSVG記号。

透過下枠の背面は静的bgC下端の反転延長。`updateBattleFloor()`が小キャンバス→WebP data URLをCSS --battle-floorへ設定、背景と寸法でキャッシュする。人物や敵の複製ではない。床の対称模様が見える場合があり専用素材化の余地あり。

## 再ビルド・本番移行時に必要なもの

```sh
python3 dev/tools/dev/battle_materials.py
python3 dev/tools/embed.py dev/naraku_src.html index.html dev/assets
```

battle_materials.pyは枠をPNGから焼く。メダルは別途元JPEGを512×512、WebP quality94で焼いている（同スクリプトにメダル処理はない）。全素材の再ビルドには既存のdev/assets一式も必要。新素材だけのコピーで他の既存埋め込み素材を欠落させないこと。

本番側の現在差分を先に確認し、src、tune.json、新UI WebP、関連コードとビルド済みindex.htmlを整合して移す。Naraku-testから本番の全履歴・全ファイルを無条件に上書きしない。開発資料や元画像はランタイム必須ではないが保管する。GitHub PagesはNaraku-test/mainのルートからlegacyビルド。今後の本番移行はユーザーの明示指示を得てから実行。

## 保存値・既知の注意

- localStorage `naraku_tune_v1` のs/x/yが焼き込み標準より優先。上下+20の新標準を見たい場合、「調整」→「初期値」で選択キャラを戻す。全セーブを消す必要はない。保存倍率にも85%描画倍率が掛かる。
- 同じ手札で再開始時にカードが左端へ重なる不具合は9cf1444で修正済み。syncDOMでカードDOM再生成時にbattleFitKeyを無効化。削らないこと。
- overflow:clipで選択カードによる横スクロールを防止。調整画面ではhandRow/ops/trayを非表示。
- 実機Safariの全条件は未検証。iPhone16想定393px幅と短い表示高をChromiumタッチで確認、ユーザーのテストで現在位置は了承済み。
- 右端カード選択時は右枠に近い。5枚のタッチ選択は成功。
