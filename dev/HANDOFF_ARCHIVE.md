## 絵（背面スプライト）の差し替えの手順（仕組みは残してある。ユーザー判断：今後もほかのキャラを入れ替えるかもしれない）

ユーザーは**静止画の比較では判断しない**（「意味がない」とのこと）。必ず実戦で動かして見比べてもらう。別のテスト用HTMLも作らない。

```bash
python3 tools/look.py add sword <新しいシート画像> [bake.py のオプション]   # 候補として焼く（assets/sword2.webp）。横6コマ×2段で1つの動きなら seq=2
# → 高画質版をビルドして公開。ユーザーは戦闘中に「調整」→ そのキャラ →「絵」の段で 今の絵／新／新6コマ を切り替えて見比べる
python3 tools/look.py promote sword                                        # 本採用（今の絵は消える）。取り消すなら drop
```

- ゲーム側は `SPR.ally['<名前>2']` があれば候補として扱う（`lookList` / `allyLook` / `setLook`。ソースの書き換えは不要）。候補が無いあいだ「絵」の段は「差し替え候補なし」と出るだけ。選んだ見た目は端末に残る（`naraku_look_v1`）。初めは「新」が出る。
- **攻撃のコマ数は素材のコマ数そのまま**（`drawAlly` が `lk.seq.length` で再生する。6コマでも12コマでもよい）。命中のタイミングは動きの55%の時点で固定。敵は6コマのまま。
- 候補が入っているあいだは絵が2つぶん入るので、軽量版が2MBを超えることがある（公開ページは問題なし）。軽量版は確定してから作る。
- 正面絵（顔・カットイン）と盤上の駒は別の素材。背面だけ替えると食い違うことがあるので、デザインを変えるときは一緒に替えるか確認する。
- **履歴**：ユズナミキを新しいシート（7680×3000、横6コマ×2段＝12コマ。デザインは同じ着物）に入れ替え済み。ユーザーが実戦で見比べて「新」に決定。

## モーションの緩急（ユーザーの指示。全モーションに適用済み）

**指示の要点**：スプライトアニメーションは全コマを等間隔で再生しない。コマの役割に応じて映す長さを変える。待機・溜め・回収は長め、加速・ヒット直前・ヒットは短め（溜め → 加速 → ヒット → フォロースルー → 回収）。ユーザーが示した12コマの成功例は 120/100/90/80/65/50/40/45/65/85/105/130ms。**この数値を全モーションに固定で使い回さず、モーションの役割に応じて相対的な長短を設計する。**

- 表は `MOTION`（データ定義の章。絵ごとに `ms`＝各コマの長さの比、`hit`＝ヒットのコマ）。味方5人と敵6種のすべてに、絵を見て役割を割り当ててある（ユズナミキは成功例の12コマの表。6コマの絵は4コマ目か5コマ目がヒット）。
- 再生は `frameAt(表, コマ数, 進み具合, 命中の瞬間)`。攻撃の長さに合わせて全体を伸び縮みさせ、**ヒットのコマが命中の瞬間ちょうどに出る**よう、ヒットより前と後ろを別々に収める。命中の瞬間は、通常攻撃＝動きの55%（`HIT_AT`）、範囲スキル＝0.16秒後（動き0.5秒の32%）、敵の近接＝0.25秒後（50%）。即時スキルと敵の遠距離は素の配分のまま。
- **見た目だけの変更で、戦闘の結果は変わらない**（命中の瞬間・攻撃の長さは触っていない。smoke.py の勝率も同じ）。
- 新しい絵を入れるとき：`MOTION` にその絵の表を足す（コマ数が合わない・表が無い絵は `MOTION_DEF` の仮の配分で動く）。smoke.py が「ヒットが最短・待機と回収が長め・回収は徐々に長い・ヒットのコマが命中の瞬間に出る」を確かめる。
- 事実：ユズナミキは攻撃間隔が0.42秒なので、成功例（合計975ms）の約43%の長さに縮めて再生している（各コマ 55/46/41/37/30/23/16/18/26/34/42/52ms。ヒット前後は60fpsで1フレーム）。攻撃の遅いキャラは動きが0.45秒で頭打ち（`animDur=min(攻撃間隔,0.45)`）。動きを長く取ると命中が遅れて戦闘の結果が変わるので、変えるならユーザーに確認してから。

配布版（画像入り）は毎回ビルドして作る。**配布版を cat / view しないこと**（base64で数十万トークンを消費する）。

python3 tools/dev/town_shots.py naraku_step4.html shots                   # 街の各画面を撮る（見た目を変えたら目で確かめる）
python3 tools/dev/run_sim.py naraku_step4.html battle                     # 難易度：戦闘の種類と深さごとの勝率（数値を変えたら回す）

**チャットに送る配布版は必ず2,000,000バイト未満にする。** 2.25MBの版を渡したところ、スマホのClaudeアプリで「戦闘UIだけ出て動かない」状態になった。ファイルを2MBで切って開くと同じ画面になる（本体スクリプトが途中で切れて一切動かない）ので、アプリ側で約2MBを超える分が切られていると見ている（仮説。1.94MBまでは動作実績あり、1.77MBに軽くしたら動いた）。Step 4でソースが約47KB増え、ユズナミキが12コマになったため、`slim.py` を軽くした（画質：atlas 70→64、cut 66→60、face 72→68。さらに**スプライトのアトラスを80%に縮小**＝`atlask=80`。コマの大きさと基準点のjsonも同じ率で直すので、表示の大きさと位置は高画質版と同じ）。街の一枚絵を入れたあとは、アトラスを76%・街の絵を幅480pxにして、上限まで約80KBの余裕。12コマのキャラを1人増やすごとに約60KB増える見込み（仮説）。

ソースの `<head>` に起動の見張りを入れてある。本体が読み込めない・止まったときは、画面上部に赤い帯で理由を出す（ユーザーにその画面を送ってもらう）。

**渡す前に、smoke.py だけでなく boot.py も必ず通すこと。** smoke.py は内部の入口を直接呼ぶので、「起動して画面を触れるか」は boot.py でしか確かめられない。boot.py は最初と最後に localStorage を消す（前回の記録が残っていると、街ではなく「探索の途中」から始まるため）。

## Step 4 で実装した内容（モジュールA：街・セーブ ＋ モジュールD軸1：装備）

**ユーザーが決めたこと**（実装前の確認への回答）：
- **狂気は探索をまたいで持ち越す。宿屋に泊まると体力と一緒に少しずつ下がる**（こちらは「教会で祓う」を勧めたが、ユーザーは宿屋を選んだ。蒸し返さない）。
- **教会の蘇生の対象は精神崩壊だけ**。戦闘不能は瀕死で戻る。戦闘で全滅したら戦利品を失い、全員瀕死で街へ帰る。
- **装備は武器と防具の2枠。落ちる数は少なめ（1探索で8〜15個）**にして、1個ずつ吟味できるようにする。
- **属性タグは「キャラ固有の属性」＋「武器の属性」の両方を持つ**（こちらは「武器で上書き」を勧めたが、ユーザーは両方を選んだ。違う属性の武器を持つと物理と魔法の両方の札が効くので強い。蒸し返さない）。

**こちらの仮決め**（ユーザーに伝えて進めた。異論は出ていない）：
- 体力も探索をまたいで持ち越し、宿屋で回復する。
- 5人とも最初から使える。出撃の3人は街（酒場）で選ぶ。
- 装備は誰でも何でも持てる（キャラ専用にするとドロップが5人に散るため）。
- 街の画面はコード描画（盤面マップと同じ、暗い革と金の調子）。絵が要るならモック絵を見せてから外部AI用プロンプトを出す。
- **層（進行度）**：奈落の主を退けると次の層が開く。層が1つ深いごとに敵の体力 +20%・攻撃力 +14%・落とす金 +30%、装備の基礎値も上がる。街の出撃ボタンの横で層を選べる。**これは仕様にもユーザーの回答にも無い、こちらの追加**（装備を集める目的を作るため）。ユーザーの感想しだいで外す・変える。
- 馬小屋（無料の宿）と「施しの蘇生」（無料の蘇生）は、金が尽きて詰むのを防ぐためのもの。
- 探索の途中で閉じたら、**たどり着いたマスの最初から再開する**（戦闘の途中は保存しない。閉じれば、その戦闘は狂気の代償なしでやり直せる。スマホではアプリが勝手に閉じることがあるので、罰は付けていない）。

**流れ**：起動 → 街（`showTown`）→ 酒場で編成と装備 → 「奈落へ出撃する」→ 探索（Step 3のまま）→ 精算（`showSettle`）→ 街。保存があれば続きから。探索の途中の保存があれば「探索の途中」画面（`showResume`）から再開。

**街の施設**（`VIEWS` と、その下の街の操作）：
- **酒場**（`party` → `char` → `pick`）：出撃の3人を左・中・右の順に選ぶ。キャラごとに武器と防具を付け替える。崩壊した仲間は選べない（外すことはできる）。
- **鍛冶屋**（`smith`）：装備の一覧（身に着けている分も含む）から選んで、強化（金と資材）か分解（資材になる）。足元に一括分解（無銘だけ／希少以下。倉庫にある鍛えていない装備だけが対象。押し直しで確定）。
- **商店**（`shop`）：灯り油・傷薬・鎮めの香を買って荷物に入れる（金90／130／170、持てる数3／3／2）。探索中はマップの「荷物」ボタンから使う（`askBag` / `useBag`）。中身は探索中の商人（`SHOP`）と同じで、街のほうが安い。
- **宿屋**（`inn`）：寝台＝金100で全員（5人）の体力が全快し狂気 −15%。馬小屋＝無料で体力が50%まで戻るだけ。泊まると1日進む。
- **教会**（`church`）：金300で蘇生（体力50%・狂気50%で戻る）。生きている仲間が3人に満たず金も足りないときは、無料の「施しの蘇生」（体力30%・狂気70%）。
- **廃屋**（`hut`）：記録の写し（1行のコード `NRK4.…`）のコピー、写しからの復元、記録の消去（押し直しで確定）。

**装備**（`[二つ名]＋装備名＋[強化値]`。例：「業火の杖 +2」）：
- 中身：`{s:枠(w/a), b:装備名の番号, r:格, p:二つ名のキー, n:強化値, pw:基礎値, id:倉庫での番号}`。`mkItem(乱数, lv, boost)` が作る。
- **ATK +n ＝ 与えるダメージ +n%（通常攻撃とスキル）。DFN +n ＝ 受けるダメージが 100/(100+n) 倍**。固定値にしなかったのは、攻撃の速いキャラだけが得をするため。
- 格（`RAR`）：無銘・希少・英雄・伝説（基礎値の倍率 1／1.2／1.45／1.8、出る割合は約62%／27%／9%／2%）。無銘には二つ名が付かない。
- 二つ名（`AFFIX`。値は格で3段階）：武器＝鋭利な（ATK）、迅雷の（攻撃速度）、遠見の（射程）、血に飢えた（会心率）、業火の（スキル威力）、早詠みの（スキル装填）、魂喰いの（ソウル獲得）。防具＝堅牢な（DFN）、不屈の（最大体力）、再生の（毎秒回復）、守護の（拠点ライフ）。
- 装備名（`GEAR_BASE`）：武器8種（長剣・戦斧・槍・短弓＝物理、杖・魔導書・宝珠・呪符＝魔法）、防具5種。
- 基礎値：`(7〜10)×(1＋0.35×lv)×格の倍率`。lv＝層−1＋マップの深さ（0〜1）。強化値 +1 ごとに基礎値 +8%（最大 +10）。
- 強化の費用：金＝40×(強化値+1)×(1+0.5×格)、資材＝強化値+1。分解で得る資材：格ごとに1／2／4／8（＋鍛えた分の一部）。
- 落ち方（`dropFor(seed, 出現番号, elite, lv, boss)`）：ふつうの敵0.25%、鎚の大鬼40%、蠍の女王は必ず（英雄以上）。奈落の主を退けると、報酬として英雄以上の装備1つと金100×層。宝箱・異変の「装備 +1」も中身のある装備になった（マスのシードで決まる）。
- 倉庫の上限は100個。あふれた分は弱いものから自動で資材になる（精算画面で知らせる）。
- 戦闘への反映は `gearStats(m)` → `newBattle` で味方ごとの `a.g`（装備の底上げ）と `a.tags`、`recalc` で `a.M`（通常攻撃の倍率）・`a.rg`（射程）・`a.sk`（スキル威力）にまとめる。**戦闘ロジックは `B.M[タグ]` ではなく `a.M` を見る。**

**セーブ**：
- `S`（街のセーブデータ）：金・資材・日数・探索と踏破の回数・層（`floorMax` / `floor`）・倉庫（`inv`）・荷物（`bag`）・出撃の3人（`picks`）・仲間5人（`roster[id]`＝体力の割合・狂気・崩壊・武器・防具）・探索の途中経過（`run`）。
- **出撃中の `P.members` は `S.roster` の中身そのもの**（コピーではない）。だから戦闘中の狂気も、勝ったあとの体力も、そのまま街の記録になる。
- 自動保存（`save` / `saveRun`）：街での操作のたび、探索の1歩ごと、マスの結果が出たとき、戦闘に勝ったとき、逆転の右手と禁忌で狂気が増えたとき。`localStorage` は必ず try/catch で守り、保存できなかった環境では街の廃屋に「自動保存なし」と出す（`SAVE_OK`）。
- 記録の写し（`exportCode` / `importCode`）：保存内容を鍵つきの乱数列でかき混ぜ、検査用の数を付けて英数字にした1行。書き換えや途中で切れた写しは弾く。本物の暗号ではない（中身を読めなくして、貼り間違いを弾く程度）。装備30個で約1700文字。
- 読み込みは必ず `fixSave` を通す（範囲外の数・知らない二つ名・枠の違う装備を直す。壊れた保存で止まらない）。
- 検証用の入口（`NARAKU.fresh` / `startRun` / `start`）は自動保存を切る（`SAVE_ON=false`）ので、テストが本物の記録を書き換えることはない。

**数値の調整場所**：`GCFG`（落ちる確率・強化の伸びと費用・層による基礎値の伸び・倉庫の上限）、`TCFG`（はじめの金・宿屋・教会・全滅時の体力・層ごとの敵の上乗せ・踏破の報酬）、`TSHOP`（街の商店の値段と持てる数）、`RAR`、`AFFIX`、`GEAR_BASE`。

**難易度と釣り合い（事実。自動操縦、4編成×5シード＝20回の探索の通し。途中で帰還しない）**：
| 装備（全員の武器と防具） | 層 | 踏破（強化を適当に選ぶ） | 踏破（火力優先） |
|---|---|---|---|
| なし | 1 | 10/20 | 6/20 |
| ATK・DFN +15 | 1 | 13/20 | 13/20 |
| ATK・DFN +30 | 1 | 18/20 | 18/20 |
| ATK・DFN +15、武器を固有と逆の属性に（両方の札が効く） | 1 | 19/20 | 17/20 |
| ATK・DFN +15 | 2 | 8/20 | 6/20 |
| ATK・DFN +30 | 2 | 12/20 | 9/20 |
| ATK・DFN +45 | 3 | 11/20 | 7/20 |
| ATK・DFN +60 | 4 | 11/20 | 7/20 |

- 装備なし・第1層はStep 3と同じ結果（戦闘ロジックが変わっていないことの確認にもなっている）。単発180秒戦も 7/12・10/12 のまま。
- **逆の属性の武器はかなり強い**（+15でも +30 相当）。ユーザーが選んだ仕様なのでそのままにしてあるが、強すぎると言われたら、両方持ちのときだけ札の効きを割り引く案がある。
- 踏破したときの持ち帰り：装備 平均9個前後（5〜14個）、金 約2100（第1層）〜3300（第3層）。
- 金の使い道の目安：寝台100、蘇生300、物資90〜170、強化は +10 まで合計で金2200（無銘）〜5500（伝説）と資材55。資材は1探索で10前後。**足りなくなるのは金より資材**（仮説：人が遊ぶと金が余る）。

**仮決め・未決**：
- すべての数値はユーザーの体感待ち（宿の値段と狂気の下がり幅、蘇生の値段、落ちる数、強化の伸び、層の上がり幅）。

## 守るべき設計ルール

1. **決定性**：戦闘ロジック（章4）はシード付き乱数だけを使う。`B.rs`（出現）、`B.rc`（戦闘）、`B.rk`（会心）、`B.ru`（強化の抽選）。`Math.random` は演出（章5・章6）専用。smoke.py が検出する。
2. **逆転の右手**：`newBattle(B.seed)` で B を丸ごと作り直す（戦闘の種類・深さ・層・戦場は `BOPT` に残っている）。戦闘中だけの状態は必ず B に置く（ソウル強化は `B.up` と `B.M`）。持ち越すもの（狂気、崩壊、逆転回数、属性タグ、体力の割合 `hpR`）は P に、探索1回分（マップ、現在地、灯り、未精算の戦利品）は R に置く。**体力と戦利品を P・R に書き込むのは勝ったときだけ**（`commitBattle`）。だから逆転の右手はマップにも持ち越しにも影響しない。
3. **ドロップ**：`dropFor(seed, 出現番号, elite, lv, boss)` で決まる（装備の中身も同じ乱数から作る）。倒す順番や巻き戻しでは変わらない。
4. **強化の提示は引き直し**：`B.ru` のシードに `P.rewinds` を混ぜてある。逆転の右手を使うと敵の出現は同じだが、提示される強化は変わる（ユーザー決定。「巻き戻しは実質のゲームオーバー」という位置づけ）。
5. **固定ステップ**：`step(1/60)` を回す。戦闘中は論理サイズ（W=360, H）を固定している。
6. **mode**：`town | map | node | battle | levelup | rewinding | victory | defeat | settle`。`town`＝街の各画面と「探索の途中」画面。`levelup` は完全停止（step も演出も止まる）。`map`＝探索のマップ、`node`＝各マスの画面（宝箱など）、`settle`＝精算。探索中かどうかは `R` の有無、マップを描くかどうかは `R&&!B` で決まる。
8. **探索の決定性**：マップの形、各マスの戦闘シード、宝箱・異変の結果は、探索のシードだけで決まる（章4の探索ロジックも `Math.random` を使わない）。マップの移動の演出（駒が滑る）は見た目だけで、`stepTo` が状態を先に進める。
7. コードの省略や「あとで実装」は禁止（ユーザーの仕様）。未実装機能は動くスタブにする。
9. **街の記録**：`P.members` は `S.roster` の中身そのもの。街と切り離したパーティが要るのは検証だけ（`makeParty`）。状態を変えたら `save()`（探索中は `saveRun()`）を呼ぶ。保存の形を変えたら `fixSave` も直す。
10. **属性タグ**：味方は `a.tags={phys,mag}` を持つ（両方 true もある）。通常攻撃の倍率は `a.M`、射程は `a.rg`、スキル威力は `a.sk`。`B.M.phys` / `B.M.mag` は札の倍率の元の値で、戦闘ロジックから直接は見ない。

- **カード23枚**（`UPS`）。同じ札は `max` 回まで重ねられ、別の軸どうしは掛け算になる（`recalc()` が `B.M` にまとめる）。
  - 物理5：剛力（威力+30%）、連撃（速度+20%）、多重撃（攻撃回数+1・最大3）、会心（15%で3倍）、剛打（押し戻し・最大3）
  - 魔法5：魔力増幅、詠唱短縮、貫く魔弾（弾が連鎖・光線が太く・最大3）、延焼（3秒燃える）、凍気（鈍足・最大3）
  - 全員3：戦意高揚（威力+20%）、疾風（速度+15%）、不屈（最大体力+20%）
  - 共通7：爆心拡大（範囲+25%）、早詠み（装填−15%）、必殺の極意（スキル威力+40%）、二重詠唱（もう一度発動）、遠見（射程+15%）、魂喰い（ソウル+25%）、拠点修復（ライフ+2）
  - 禁忌3（各1回・生存者全員の狂気+10%）：黒き衝動（攻撃速度2倍・黒いオーラ）、奈落の裁き（全体攻撃・18秒ごとに再発動）、血の盟約（与ダメージ2倍）
- **選択画面**：完全停止中に全画面で出す（サイドエリアも隠れる）。禁忌の代償と崩壊する味方の名前は札に出す。効果文 `desc` の「|」は改行してよい位置（札が狭いので語の途中で折り返さないための印）。
- **札の絵の受け口**（`UPARTS`）：`assets/upart_<キー>.webp` を置いてビルドすると差し込まれる。キーは札のid（その札専用）か系統名 `phys / mag / all / common / taboo`（系統共通）。専用→系統共通→紋章（`g` の一文字）の順で使う。絵は4:5の縦長、320×400px程度で十分。まず系統共通の5枚から作る方針。
- **確率誘導**：物理・魔法の札の重みは `1＋0.5×その属性の生存人数`（0人なら出ない）。全員0.7、共通1.0、禁忌0.3（強化2回目以降・1回の提示に1枚まで）。選択画面に「出現率×1.5」のように表示する。
- **固有の属性タグ**（`CHAR_TAG`）：ユズナミキ・ラナ・アベニウス＝物理、シェリ・マリアンヌ＝魔法。Step 4で、これに武器の属性タグが加わる形になった（`gearStats(m).tags`）。
- **禁忌の狂気は P に入る**ので、逆転の右手で強化が消えても狂気は残る。崩壊する味方がいる場合は札に名前を出して警告し、生存者が全員崩壊する札は選べない。
- **敵インフレ**（`CFG`）：出現間隔 `1.4×e^(-t/62)`（下限0.1秒）、体力倍率 `1＋t/180＋(t/100)²`（最大5.2倍）、攻撃力倍率 `1＋t/450`、大群は30秒ごとに `5＋4×回数` 体。180秒で約860体、同時に画面にいる敵は最大150〜200体。

## 仮決め・未決事項

- 単発180秒戦（`trial`。Step 2でユーザーが触って調整した基準）の難易度：自動操縦の20戦で、強化なし0勝、強化を適当に選ぶと12勝、火力優先で選ぶと16勝（smoke.py の12戦では7勝と10勝。Step 3の改修後も同じ結果で、戦闘ロジックが変わっていないことの確認になっている）。探索中の戦闘の難易度は上の「Step 3 で実装した内容」を参照。
- キャラ調整の履歴（Step 2中にユーザーと決定）：近距離が通常攻撃で空振りしがちだったため、ラナを射程110→135・半径50→62・威力26→34、アベニウスを射程150→170・威力14→18に。シェリは光線が細く平均2体にしか当たらなかったため、幅18→30・攻撃間隔1.9→1.6秒に。その分、敵の体力と攻撃力の伸びを引き上げた。マリアンヌは通常DPSが最下位だが回復役なので据え置き。
- 結果画面にキャラ別の与ダメージ／秒（通常とスキルの内訳）を表示している。集計は `B.stat[id]={atk,skill,taken}`（`hurt()` の who / kind 引数で振り分け）。
- 同時150〜200体の描画は、ユーザーのスマホで公開ページ（高画質版）を動かして「大丈夫」との返事。
- 黒いオーラ、奈落の裁き、延焼の見た目はコード描画の仮のもの。強化の札の絵は系統共通の5枚（phys=大剣 / mag=魔導書 / all=軍旗 / common=ランタン / taboo=黒い右手）を組み込み済み。札ごとの専用絵は未作成で、紋章の一文字で区別している。元画像は1122×1402で、中央を4:5に切り出して288×360のWebPにした。
- 蠍の女王は強化が噛み合えば倒せるが、基本は「耐え切る相手」のまま。
- アベニウス入りの編成がやや強い（Step 1から継続）。
- 手札スキルカードの見た目の強化は別フェーズ（ユーザー判断）。強化の札の絵は系統共通の5枚で当面は十分。
- 背景・UIの絵は外部AI（ChatGPT）で作る運用。組み込み済み：`assets/ui_leather.webp`（操作エリアとサイドエリアの地。端をなじませた継ぎ目なしタイル）、`assets/ui_rewind.webp`（逆転の右手の演出絵。黒背景を `mix-blend-mode:screen` で重ねる）。受け口は `const UI`（`ui_<名前>.webp`）。
- 戦場の背景（真上から見た床の絵）：A石畳の回廊 `bg_corridor`／B地下墓地 `bg_crypt`／C腐れ根の洞 `bg_roots` を組み込み済み。D水没した聖堂 `bg_chapel`／E灰の焦土 `bg_ash`／F儀式の間 `bg_ritual`（ボス）はプロンプトを渡してあり生成待ち（キー名は `BG_NAMES` に定義済みなので、`assets/bg_<キー>.webp` を置いてビルドすれば選択肢に出る）。
  - **橋や穴がある絵は敵が宙に浮くので不可**。「真上から見た、端から端まで同じ高さの床」だけを描かせ、門の光・防衛線・周辺の暗さは `buildBG()` がコードで重ねる。
  - 元画像は縦長1024×1536。左右を80%に切ってから480×900のWebP（q=62）にしている。画面には中央の約7割が映る。
  - 戦場は `B.bg` に入る。探索中は `bgFor(深さ,種類)` がマップの深さで決める（Step 3で編成画面の「戦場」ボタンは外した）。`bgPick` と `NARAKU.setBg` は検証用に残してある。
- タイトル画面の背景は作らない（ユーザー判断。まだモジュール開発の段階のため）。

## 既知の注意点

- ラナとマリアンヌのスプライトは解像度が他の約3分の1。高さ724pxでの再出力をユーザーに勧めてある（任意）。
- 鎚の大鬼は4・5コマ目だけ元画像が紫がかっている（素材由来）。
- 軽量版は1,926,958バイト（上限2,000,000）。戦場の背景を1枚足すごとに約0.06MB増える。足りなくなったら `slim.py` の `atlask`（アトラスの縮小率）や画質を下げる。公開ページ（高画質版・約3.7MB）は上限16MBなので当面は気にしなくてよい。
- セーブは `localStorage`。公開ページでは動くが消えることがあり、チャットのプレビューでは保存が効かない可能性が高い（どちらも実機では未確認。ユーザーの報告待ち）。効かない環境では廃屋の札に「自動保存なし」と出る。
- ユーザーはスマホ（Claudeアプリ）で確認している。返信は「結論→詳細→要約結論」、事実と仮説を分ける。提案は可否を聞いてから実装するが、ゲームデザインは「仮実装して触って判断」の進め方が好評。
- 見た目の相談は、**ラフなモック絵を1枚出して判断してもらう**と早い（Step 3で、マップの方向性・サイドエリアを閉じる案・彫り線をこの方法で決めた）。外部AIで作った素材は、**組み込む前に実寸で盤に置いた画像を見せてレビューする**（ユーザーの希望。没なら組み込まず、プロンプトを作り直す）。こちらが見送りを勧めても、ユーザーが採用を決めた素材はそのまま使う。
- 外部AI（ChatGPT）用の画像プロンプトは、1件ずつ別のメッセージで送る（スマホでコピーしやすいように）。
- バランスの相談には、シミュレーションの数字（10戦程度でよい）を添えて答える。
